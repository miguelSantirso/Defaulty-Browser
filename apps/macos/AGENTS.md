# AGENTS.md — macOS app

Read the root `AGENTS.md` and `docs/product-spec.md` first. This file covers the Swift/AppKit
implementation only.

## Stack

- Swift 6 language mode, SwiftPM (`swift-tools-version: 6.0`), minimum macOS 13.
- AppKit agent app: `NSStatusItem` + native `NSMenu`, `LSUIElement=true`, no Dock icon.
- Ad-hoc signed for local use; no sandbox, no notarization.

## Layout

```text
apps/macos/
├── Package.swift
├── Sources/DefaultyCore/       # testable domain logic (no UI)
├── Sources/Defaulty/           # AppKit lifecycle, status item, CLI probes
├── Tests/DefaultyCoreTests/    # XCTest
├── Resources/Info.plist        # bundle metadata (LSUIElement, icon, category)
├── Resources/AppIcon.icns      # generated by Scripts/make-icon.swift
└── Scripts/build-app.sh        # assembles + ad-hoc signs build/Defaulty.app
```

## Commands

Run from `apps/macos/`:

```sh
swift build
swift build -c release
swift test
make verify        # tests + app bundle + plist + signature
make app           # build/Defaulty.app
make run
make install       # INSTALL_DIR ?= /Applications
make clean
```

From the repo root, use the namespaced equivalents: `make macos-*`.

## Implementation rules

- **Discovery:** `NSWorkspace.urlsForApplications(toOpen:)` for `http` and `https`; resolve each
  bundle to its canonical app URL, deduplicate by bundle identifier, and sort with
  `localizedStandardCompare`. Do not use deprecated `LSCopyAllHandlersForURLScheme` or
  `LSSetDefaultHandlerForURLScheme`.
- **Current default:** `NSWorkspace.urlForApplication(toOpen:)` with an `https` probe URL.
- **Switching:** `NSWorkspace.setDefaultApplication(at:toOpenURLsWithScheme:completion:)` for
  `https` then `http`. Await both. Do not block the main thread while awaiting; completion
  handlers are delivered on the main run loop.
- **Concurrency:** keep UI and `DefaultBrowserService` on the main actor. Guard continuations
  against double resume. The project builds under Swift 6 strict concurrency.
- **Menu:** rebuild in `menuNeedsUpdate` so it is always truthful. The checked item stays
  enabled. Refresh states immediately after a successful or failed change too.
- **Status item:** use a template SF Symbol, set a tooltip and accessibility label naming the
  current default, and update them on refresh.
- **Errors:** native `NSAlert` with a recovery hint; activate the app before presenting it.
- **No prefs, no network, no background helpers.**

## CLI probes

The executable supports read-only testing and one deliberate write mode:

```sh
build/Defaulty.app/Contents/MacOS/Defaulty --list
build/Defaulty.app/Contents/MacOS/Defaulty --current
build/Defaulty.app/Contents/MacOS/Defaulty --set-default <bundle-id>
```

Run the binary inside the `.app` so `Bundle.main` metadata is correct. `--set-default` changes
the host machine's default browser — use it only for deliberate validation and restore the
previous default afterward.

## Testing rules

- Unit tests must not touch the system default browser.
- The Launch Services integration test is read-only; keep it tolerant of machines with
  different browser sets.
- After changing discovery, service, or packaging, run `make verify` and the read-only CLI
  checks in `docs/validation.md`.
- Visual checks require the user; ask them to run the macOS checklist and report back.

## Packaging notes

- `Scripts/build-app.sh` builds release, copies the executable, `Info.plist`, `PkgInfo`, and the
  optional icon, then ad-hoc signs and verifies. A failed verification must fail the build.
- `make install` defaults to `/Applications`; it creates the destination if needed.
- Build outputs (`build/`, `.build/`) are ignored. Never commit them.
- Regenerate the icon with `swift Scripts/make-icon.swift` only when the brand design changes.

## Known edge cases

- macOS may require user consent before applying a default-handler change.
- Launch Services can report handlers from alternate volumes; always canonicalize.
- An app may register for only one scheme. The service attempts `https` then `http`; report
  failures instead of pretending success.
- Clicking the already-checked browser re-applies both schemes, which is harmless and repairs
  partial registrations.
